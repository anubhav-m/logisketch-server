# D2

## Structure
Shapes are created by naming them: `server`. Labels: `server: API Server`. Connections:
`a -> b`, `a <- b`, `a <-> b`, `a -- b`, with labels `a -> b: calls`. Comments start with `#`.
`direction: right` at top level changes layout. No semicolons needed, no wrapping block.

## Shapes and styles
Set a shape with a block: `db: Orders DB { shape: cylinder }`. Shapes: `rectangle`, `square`,
`circle`, `oval`, `diamond`, `cylinder`, `queue`, `person`, `cloud`, `hexagon`, `page`,
`package`, `sql_table`, `class`. Style: `server.style.fill: "#f0f0f0"`.

## Containers for architecture diagrams
Nest shapes inside a container: `backend: { api; worker }`. Refer to nested shapes with dots:
`client -> backend.api`. Containers can have labels: `backend: Backend Services { ... }`.

```d2
direction: right
user: User { shape: person }
backend: Backend {
  api: API Server
  worker: Worker
}
db: PostgreSQL { shape: cylinder }
queue: Jobs { shape: queue }
user -> backend.api: HTTPS
backend.api -> db: SQL
backend.api -> queue: enqueue
queue -> backend.worker: consume
backend.worker -> db: update
```

## ER diagrams with sql_table
Each table is a block with `shape: sql_table` and one `column: type` per line. Constraints:
`id: int { constraint: primary_key }`, `foreign_key`, `unique`. Relationships connect columns:
`orders.user_id -> users.id`.

```d2
users: {
  shape: sql_table
  id: int { constraint: primary_key }
  email: varchar { constraint: unique }
}
orders: {
  shape: sql_table
  id: int { constraint: primary_key }
  user_id: int { constraint: foreign_key }
  total: decimal
}
orders.user_id -> users.id
```

## Flowcharts and common mistakes
Decisions use `shape: diamond`; label branches on the edges: `check -> save: yes`.
Common mistakes: using `-->` (D2 uses `->`), Mermaid or PlantUML headers, unbalanced braces,
keys with spaces that are not quoted (`"web app"` or use `web: Web App`), and reserved keywords
(`shape`, `style`, `label`, `direction`) used as shape names.
